# Blender ship & crew assets (GLB contract)

Ships are procedural (`src/ships`) **except** the ones that have a GLB in `public/models/ships/<id>.glb`.
`createShip(spec)` uses the GLB when it is loaded; otherwise it returns the procedural ship at once and swaps in the GLB under the same
`root` when the model arrives (`ships/lazyShip.ts`; `requestShipAsset(id)` loads one model on demand, `loadShipAssets(ids)` preloads), so a missing or broken file
never stops the game and only the ships that are shown are fetched. All 16 ships have a GLB, all from the one generic builder
(`tools/blender/make_ships.py`, a Python port of `src/ships` driven by `tools/blender/ships.json`; the local Llama runs it, see `BLENDER_PIPELINE.md`).
**All 16 ships are *PBR ships* with baked textures (section below)**; the flat-colour atlas builder (`shipbuilder.py`) and the flat-colour contract described in the rest of this file are kept as the reference/legacy path (`PBR_IDS` in `make_ships.py`). `tests/assets.test.ts` enforces this contract for every ship.

## Ship GLB
Space: glTF Y-up export of Blender Z-up, +x bow, +y up, +z starboard, metres, waterline y = 0 (Blender +Y is port; glTF z = −Blender y).

| Node | Rule |
|---|---|
| `<id>` | root empty |
| `LOD0`, `LOD1`, `LOD2` | one child group per level; the game only toggles `.visible` (LOD0 is the hero model) |
| `LODn_Body` | static hull, deck, mast, rigging, jib … merged by material |
| `LODn_trim-aft` | (legacy hand-made tartane only; no shipped ship uses it any more, the game still accepts it) **sail pivot on the mast axis at deck height** (translation = `meta.trimPivot`). The game rotates it about Y for the brace/sheet swing; LOD0 sails are then moved by the cloth shader (see the cloth contract below), the other LODs are scaled in Y/Z for sail level and wind side. Square rigs use `LODn_trim-square`. `setSailTrim` matches on `endsWith('trim-aft' / 'trim-square')` |
| `LODn_AftSail` | yard + sail, pivot-local, child of the pivot |
| `LODn_m<i>_trim-square` / `_trim-aft` | the generic builder (every ship): one pivot per sail group of mast `i` (square sails, and the spanker/gaff/lug/lateen sail), sails named `LODn_m<i>_SquareSail` / `_AftSail` |
| `LOD0_Glass` | generic builder: emissive stern windows and lanterns (LOD0 only) |
| `LOD0_LanternGlass` | legacy tartane only; the generic builders use `LOD0_Glass` above |

- **Names:** letters, digits, `_` and `-` only. `GLTFLoader` strips dots, and Blender adds `.001` to duplicates, so a clash silently renames a node.
- **Budgets (flat-colour ships)** scale with length `L`: LOD0 ≤ 1700 + 140 L, LOD1 ≤ 160 + 20 L, LOD2 ≤ 60 + 6 L (written to `meta.budgets` and re-checked by the tests); LOD1 < 30 % and LOD2 < 60 % of the level above. LOD0 is 2–6 draw calls (body, one per sail pivot, glass).
- **Full-quality extras (LOD0 only, flat-colour ships):** cannon muzzles in the ports, rudder, an anchor on each bow, ratlines between the shrouds, a hatch coaming in the waist and up to three cargo barrels (both deck obstacles in `meta.json`), deck plank seams, hull plank lines, rivets on the wale, a stern lantern post (ships without a sterncastle) and smooth-shaded sails.
- **Materials (flat-colour ships):** at most 3 for the whole file: one `*_atlas_mat` (4×4 flat colour swatches, 256 px, every face maps to one swatch centre), the emissive glass and `*_flag` (pennants and the stern ensign, node `LODn_Flag`; the game clones it per ship and gives it the nation's ensign texture; the colour is only the fallback). Colours stay editable in `<id>_atlas.png`; faces never need unique UVs.
- **LODs are regenerated by rule, not decimated** (`tools/blender/shipbuilder.py` `LOD_CFG`): fewer hull stations/ring points, no seams/rivets/props, a coarser sail grid, 4/6-sided spars. The wale (cream band) is baked into the hull swatches at LOD1/2 so the colour does not pop when the level changes.
- **Bounds:** length (stern to bowsprit tip) at least `spec.length`; every ship ≤ 1.15 × + bowsprit + 1 m; beam within −10 %/+15 % of `spec.beam` plus 1.2 m for muzzles and anchors (and up to 0.4 L for oared ships); keel below the waterline.
- **Spec link:** generated ships carry `meta.specHash` (FNV-1a of the canonical spec JSON); the tests recompute it from `specs.ts`, so changing a spec fails them until the ship is regenerated. Sail pivots must sit on their mast base (`(0.5 − at)·L`) on every LOD.
- **Size:** every flat-colour ship < 500 KB (largest today: frigate 389 KB, embedded atlas included); PBR ships see above. No KTX2 yet.

## PBR ships (`meta.pbr = true`, all 16)
Built by `tools/blender/pbrship.py` (geometry) + `pbrhull.py`/`pbrtex.py` (numpy textures). Same node contract, space and pivots as above; what differs:

| Item | Rule |
|---|---|
| Materials (5) | `<id>_atlas` (hull, deck, castle roofs, small metal parts: **unique UVs**), `<id>_wood` (tiling planked wood, tinted per vertex: castle walls, bulwarks, spars, rails, boats), `<id>_sail` (tiling canvas), `<id>_glass` (emissive, `LOD0_Glass`), `<id>_flag` (`LODn_Flag`, tinted by the game). All except glass/flag are `MeshStandardMaterial` after loading: `map`, `normalMap`, and one packed **ORM** image (R occlusion = `aoMap`, G roughness, B metalness) |
| Images (9) | atlas `A`×`A` (1024 tartane, 1536 brig, 2048 galleon/battleship; about 20 mm per texel along the hull), wood 512², sail 512²; each as albedo + normal + ORM, **WebP** (`EXT_texture_webp`, quality 82) |
| Atlas layout | hull = the unwrapped *half* hull (u = station, v = girth, rail on top, keel at the bottom; both sides share it): planks, caulked seams, wales, gun ports with frames, weed/barnacle waterline, copper sheathing (brig and bigger) or tar, streaks and salt; deck = u station, v = \|z\|/half width (planks, butt joints, nails, wear); a 4×4 swatch block for flat colours (iron, brass, gilt, rope, …). Regions are padded 8 px (mip bleeding). `pbrlayout.py` is the single source of the layout and of the gun-port/wale positions, so texture and geometry agree |
| Tiles | wood tile = 2 m × 2 m, 8 plank rows (row 2 has no seams: spars sample it for grain); sail tile = 1.1 m, two vertical cloths with stitched seams; UVs are metres / tile size (`pbrmesh.py`), sail cloth keeps the same scale on every sail |
| Vertex colours | every body/sail mesh carries `COLOR_0` = part tint × **baked ambient occlusion** (`pbrao.py`: 6–10 rays per vertex into the whole ship); sails also carry a dirt/leech/reef-band/mildew pattern. `glbShip` still scorches sails by multiplying `material.color` |
| Geometry | `meshopt` compressed (`EXT_meshopt_compression`; `assets.ts` installs `MeshoptDecoder`). Smooth shading on hull, tubes, lathes; faceted on boxes |
| Nodes | `LODn_Body` (atlas), `LODn_Wood`, `LODn_Jib` (static headsails, sail material, scorched like the sails), under each pivot `LODn_m<i>_<Kind>Sail` + `LODn_m<i>_<Kind>Yards` (yards, boltropes, lifts, footropes: they trim with the sail), `LOD0_Glass`, `LOD0_Flag` (pennant, ensign; LOD0 only) |
| Budgets | LOD0 ≤ 8000 + 700 L, LOD1 ≤ 600 + 95 L, LOD2 ≤ 300 + 35 L (`meta.budgets`, same formula in the tests); LOD1 < 30 % and LOD2 < 60 % of the level above |
| Size | < 2.2 MB per GLB |

Content of the full-quality LOD0: planked hull with wales and gilt/trim bands, copper sheathing, gun ports with frames, lids (lower decks) and iron muzzles, weather-deck guns on carriages, bulwarks with stanchions and cap rails, castles with panelled walls, balustrades, doors and cabin windows, a stern gallery (windows with mullions, gilt cornices), quarter galleries, figurehead and beakhead, cathead and two anchors, rudder with pintles, keel and stem, hatch with grating, capstan, barrels, ship's wheel and binnacle, longboat on skids and a jolly boat on davits (galleon, battleship; the brig only has the jolly boat), lanterns, masts with iron hoops, tops, crosstrees, caps, crow's nest (tall masts), channels and deadeyes, shrouds with ratlines, backstays and stays with sag, bowsprit with bobstay and jibs, yards with blocks, lifts and footropes, sails with boltropes and tattered feet, pennant and ensign; small ships get oars, baskets, nets and a cuddy. LOD1 keeps hull (all painted detail comes from the textures), deck, castles, masts, yards and coarse sails (about 7–12 % of LOD0); LOD2 is a silhouette.

## Cloth contract (sails, jibs, booms and flags drawn by vertex shaders)
The shaders need **nothing baked** into the GLBs; the game analyses the shipped meshes when a ship is built (`src/ships/clothGeometry.ts`, `clothRig.ts`, `flagCloth.ts`; `tests/clothGlb.test.ts` runs it on all 16 and fails when any sail, jib, yards or boom mesh of any LOD is left without a cloth material or has a vertex the shader would leave frozen; the frozen check runs a CPU copy of the GLSL gather in `tests/clothReference.ts`, and `tests/clothReference.test.ts` pins the exact GLSL expressions the copy mirrors, so the two cannot drift silently, but the GLSL itself is only ever compiled in a browser). What the generator must keep true, **at every LOD** (LOD1 and LOD2 are the same structure with coarser grids):
- `LODn_m<i>_SquareSail` is one welded quad grid **per tier**; the tiers of a mast are **separate grids with a gap** (the connected components of the index buffer are the tiers, sorted by height; at LOD0 their number must equal `spec.masts[i].tiers`). The grid is a plane in y/z with the baked belly along +x, rows run from the foot (bottom) to the yard (top).
- `LODn_m<i>_AftSail` is one grid in the x/y plane with the baked belly along +z; its upper and lower outlines (as functions of x, 48 bins) are the head and foot lines. Its corners (tack, clew, peak) have no height of their own, so the shader shrinks them towards the head anchor while the sail is gathered (no frozen tips).
- `LODn_Jib` holds one connected grid per jib (1-3), numbered from the lowest up (cloth codes 5, 6, 7: each jib has its own furl and belly uniform). The tack is the most forward vertex (the bowsprit end), the head the highest; the jib is hauled down towards its tack along the stay (the luff stays on the stay), belly along z.
- `LODn_m<i>_SquareYards` holds the yards, footropes, boltropes and lifts of all tiers as separate connected pieces; each piece belongs to the tier it starts in (its lowest point) and is gathered like that tier's sail except within a yard's thickness of the head line, so yards never move. `LODn_m<i>_AftYards` (boom, gaff) follows the sail: every vertex is placed between the sail's head and foot lines at its x, so the gaff stays and the boom is lifted when the sail is furled.
- `LOD0_Flag`: every pennant and the ensign is its own strip streaming towards **-x** from its pole (the +x end); strips need not share vertices (flat quads are welded by position). The UV may be anything: `prepareFlag` rewrites it at load time to map the nation ensign (`flagArt.ts`); strips thinner than 0.3 of their length are pennants and sample the texture's plain colour strip.
- Per-vertex data the game adds in memory (never in the file): `clothA` = (code 1-3 square tier slot, 4 fore-and-aft, 5 jib, +10 for rigging; v foot to head; u across; baked belly in metres), `clothB` = (head-line y, height, width, seed; jib: tack x, y, size, seed), `clothC` = (head anchor x, y, tallest height, 1 - tip weight), `flagA` = (distance along the cloth, depth below the pole top, strip length, seed), `flagP` = pole point. Meshes without them (static spars) are not moved.
- Material rules: each ship clones the sail, yards and flag materials per LOD (scorch and nation tint stay per ship) and patches the clones with `onBeforeCompile` plus a fixed `customProgramCacheKey`, so all ships share one GL program per kind (sail/yards/jib `cloth-sail-2`, its depth, lit flag, unlit procedural flag, flag depth). LOD1/LOD2 use the same shader with `uDetail = 0` (no flutter or folds: furl, belly and tear only, with the same furl order, so a level switch does not pop); the pivots of every level only swing. Every cloth mesh gets a `customDepthMaterial` with the same displacement. The procedural ships' sails (9 x 9 grids), jibs (7 x 7), booms/gaffs and flags use the same modes (their cylinders are baked into pivot space and get a private patched wood material).
- The LOD0 sail meshes need at least about 15 x 11 vertices per tier so the folds have something to bend.

### Baked flutter (`public/models/cloth/`)
`flutter.bin` (RGBA16F texels, about 0.39 MB) + `flutter.meta.json` are written by `npm run bake:cloth` (`tools/cloth/solver.ts`: a deterministic Verlet membrane solver on a normalised 16 x 12 grid using only `+ - * /`, `sqrt` and `floor`, fixed seed, pinned edges, periodic wind forcing, settle, then a cross-fade so the 32-frame loop is seamless): 3 aspect bands (tall 1.6, square, wide 0.6) x 2 amplitude levels (peak 0.006 and 0.02 of sqrt(area)), one static fold layer, and a flag strip (pole edge driven, tip free) at 2 levels; texel = (z, dz/dx, dz/dy). One texture array is shared by every ship (`src/ships/clothBake.ts` loads it once from `createShip`; `uFlutter` blends the two levels, the sail's seed is the loop phase, two frames are blended linearly). Furl, belly and tear stay analytic. Until the bake has loaded, or if it fails to load, the shaders use their analytic flutter (same program, `uBakeInfo.x = 0`). `tests/clothBake.test.ts` checks that the shipped files are exactly what the solver writes (rerun the bake after changing it), that every loop is seamless, that the CPU reference sampler (`bakeFlutter`) follows the GLSL, the fallback and that no new GL programs appear. RGBA16F is used everywhere (WebGL2 always filters it); there is no RGBA8 variant, the analytic path is the fallback.

### Frame cost of the cloth
`lab16` harness (16 ships, one per type, all at LOD0, 1024 x 768, sun shadows on, sails and wind changing every frame, mean of 150 frames with `gl.finish()` so the GPU is included; the dev browser pane's software-ish GPU, so only the differences mean something; second of two runs shown):

| Build | draw calls | frame ms | GL programs | triangles |
|---|---|---|---|---|
| no cloth (`a9d170f`, scaled sails, static flags) | 146 | 2.8 | 4 | 305.8 k |
| cloth v1 (`fffd7b4`: LOD0 sails and flags) | 156 | 4.0 | 8 | 311.4 k |
| cloth v2 (all LODs, jibs, booms, baked flutter) | 156 | 4.1 | 8 | 311.4 k |

With `?perf` in the real game (sailing, 12 NPC ships, medium quality, 1024 x 768, v-sync bound): 12.1 ms / 82 fps and 210-222 draw calls with and without the cloth. The extra draws are the depth passes of the cloth meshes; the programs are shared by the whole fleet, so neither number grows with more ships.

## `<id>.meta.json` (written by the generator, read by `ships/deck.ts`)
`lods` (tris/meshes/drawCalls, must equal the GLB), PBR ships also `pbr: true`, `atlasPx`, `tilePx`; `trimPivot`, `lantern`, `deck.stations` (`[x, y, halfWidth]` per hull station: deck height and **walkable** half width, already inset from the rail and 0 where the bow is too narrow) and `obstacles` (circles/rects in ship-local x/z: mast, hatch, barrels, anchor, tiller, lantern pole). Crew AI walks only where `Deck.walkable(x, z, radius)`.

## LOD policy in the game
- `ships/lod.ts`: `LOD_RANGES = [5, 18]` ship lengths (tartane ≈ 60 m / 216 m), 12 % hysteresis, and a staggered refresh (`lodUpdateDue`).
- **The player's ship is never switched** (always LOD0). `render/fleet.ts` switches the other ships (`GameView.others`) and skips ships beyond 1,100 m. Distant ships also skip wave pitch/roll sampling.
- Debug: `?perf` publishes `window.__perf = {fps, calls, triangles, lods, crew, others}`; `?lod=0|1|2` forces every other ship to that level.
- Measured once with 4 patrols (tartane, sloop, brig, galleon; not re-measured with 12) the triangles were dominated by the ocean mesh (~260 k) and LOD saved only ~5 k; the NPC fleet is now 12 ships (tartane … battleship), where the ladder matters more. Re-measure with `?perf&lod=0|1|2`.

## Crew GLBs (`public/models/crew/`)
See `CREW.md`. Loaded by `render/crew.ts`; appearance (variant, palette indices, hair/hat/beard) comes from `gameplay/crew.ts` through `CrewView`. Materials are cloned per sailor and tinted (`material.color`), the clips are crossfaded with `crossFadeTo` (never park an action at weight 0).

**Known gap:** `gameplay/game.ts` reads `getDeck(spec.id)` once at `createGame`; with lazy loading the deck exists only after the ship's GLB has loaded (normally by the gallery, which shows the ship first). `main.ts` should `await requestShipAsset(spec.id)` before starting sailing (outside `src/ships`, not done here).

## Props (`public/models/props/`)
**`debris.glb`** + **`debris.meta.json`**: cannon-hit debris, built by `tools/blender/make_debris.py` (`blender -b --factory-startup --python tools/blender/make_debris.py`; numpy textures from `pbrtex.py`, WebP + meshopt like the PBR ships). Nine separate top-level meshes, **one shared material** (512 px atlas: weathered wood, tarred wood, sailcloth, hemp rope quadrants; albedo + normal + packed ORM; `COLOR_0` tints, warm "fresh" tint on torn plank ends). Real metres, origin at each piece's bounding-box centre, +Y up, 40-300 triangles each, GLB under 400 KB (about 105 KB). The cloth material is double-sided.

|---|---|---|
| `Plank_L` / `Plank_M` / `Plank_S` | wood | 1.21 / 0.63 / 0.30 long, about 0.2 / 0.16 / 0.12 wide, 0.05 thick |
| `Splinter_A` / `Splinter_B` | wood | 0.56 / 0.36 long, thin jagged shards |
